# ReuseBeacon 上手指南

[English](USAGE.en.md) · [首页](../README.md) · [项目实践](../PROJECTS.md) · [测试与证据](../evaluations/README.md)

从一个实际开发任务开始：为现有项目增加功能、比较技术方案，或补充专门的开发工作流。下面的提示词可以直接复制，并按项目需求调整。

## 1. 安装到当前项目

在项目目录的终端运行（需要 Node.js 22.20.0 或更新的兼容版本）：

```shell
npx skills@1.7.0 add xtltt56-cmd/reusebeacon --skill reusebeacon --copy
```

按提示选择正在使用的 Agent，安装范围选择当前项目。已有可用安装时直接进入下一步。

[固定 v0.3.2 或指定 Agent](../README.md#安装) · [ZIP 手动安装](../README.md#手动安装-zip)

## 2. 在任务中调用

按工具要求刷新技能列表或打开新会话，选择 ReuseBeacon，或明确写“使用 reusebeacon”。支持 `$` 调用的工具可使用 `$reusebeacon`。

请选择项目确实需要的功能，并补充现有的输入、输出和验收要求。已明确的小修复可以直接处理；这类任务通常无需额外的选型与发现流程。

### 示例一：实现功能

适合给现有应用增加导出能力，检查项目已有依赖和适用的成熟实现。

```text
使用 reusebeacon，给当前项目增加 Excel 导出功能。
沿用现有技术栈，优先复用已有依赖或适用的成熟库，保留字段和数据类型，完成实现与测试。
```

查看采用的实现与版本、代码差异和实际测试结果。导出功能应生成可打开的文件，并验证字段、数据类型及项目要求的边界情况。

### 示例二：只做选型

适合先了解方案和集成成本，再决定如何实现。

```text
使用 reusebeacon，比较适合当前项目的定时任务实现。
结合时区、运行环境和现有依赖给出采用建议，暂不改代码。
```

查看候选来源、对应版本和影响选择的依据，确认建议覆盖实际需求。研究任务到建议为止；决定实施后再给出实现要求。

### 示例三：补充开发工作流

适合需要浏览器测试等专门流程，并希望寻找和使用合适的辅助 Skill。

```text
使用 reusebeacon，为现有网页补充浏览器端到端测试。
先使用已有工具和 Skill；确有缺口时，查找合适的 Skill，在当前项目安装并实际使用，验证主要用户流程。
```

查看采用的 Skill 来源、安装位置、实际调用和测试结果。浏览器工具等执行能力需要由宿主提供；下载 Skill 本身不能补齐缺失的工具。

## 3. 查看交付结果

重点查看本次改动、复用来源和实际检查结果。需要核查案例时，见[作者项目的源码与测试](../PROJECTS.md)；需要比较其他方案时，见[各批次评测](../evaluations/README.md)。

## 常见问题

| 现象 | 下一步 |
| --- | --- |
| 技能列表中找不到 ReuseBeacon | 核对安装时选择的 Agent 和项目目录，按工具说明刷新或开启新会话；手动安装时保留完整技能目录。 |
| 安装后没有调用 | 在技能选择器中选中它，或在需求中明确写“使用 reusebeacon”；自动匹配因工具和模型而异。 |
| 无法访问外部资料 | 报告失败的来源与错误，使用可用的官方资料或本地实现；离线任务明确写出离线约束。 |
| 辅助 Skill 安装了但无法执行 | 核对宿主是否具备它需要的工具、权限与运行环境，再查看实际加载方式。 |
